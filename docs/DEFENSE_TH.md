# สรุปงานสำหรับนำเสนอและตอบคำถามอาจารย์

## สรุปที่พูดได้ในหนึ่งนาที

งานนี้ศึกษาว่า self-supervised learning (SSL) แบบให้โมเดลเติมสัญญาณเซนเซอร์ที่ปิดบังไว้ ช่วยจำแนกกิจกรรมมนุษย์หรือไม่เมื่อมีป้ายกำกับสำหรับฝึกน้อย เปรียบเทียบ 1D CNN แบบฝึกจากศูนย์กับ SSL ที่ปิดบังเวลา ช่องสัญญาณ และทั้งสองแบบ ใช้ UCI HAR โดยแยกคนใน train, validation และ test ไม่ให้ซ้ำกัน รัน 4 ระดับป้ายกำกับ × 4 วิธี × 3 seed = 48 ชุด และประเมินสัญญาณปกติ/ขาด accelerometer/ขาด gyroscope รวม 144 ผล

เมื่อมี training labels 1% หรือ 61 หน้าต่าง SSL แบบปิดช่วงเวลาได้ Macro-F1 72.00 ± 1.47% เทียบกับ supervised 68.52 ± 0.84% ต่างกัน +3.48 จุดเปอร์เซ็นต์ ส่วน SSL แบบรวมเวลาและช่องได้ 68.95 ± 2.06% ซึ่งดีขึ้นเพียง +0.43 จุด งานนี้แสดงว่าการเลือก pretraining objective มีผล และการรวม mask มากขึ้นไม่ได้ช่วยเสมอ ภายใต้ข้อมูลนี้และ protocol นี้

ที่ 5% และ 10% SSL-time ให้คะแนน clean test 84.86% และ 89.01% เทียบ supervised 82.85% และ 87.68% ตามลำดับ ที่ 100% ทั้งสองวิธีใกล้กัน (91.26% เทียบ 90.92%) ไม่ควรพูดว่าความต่างนี้พิสูจน์ว่า SSL เหนือกว่าโดยทั่วไป เพราะมีเพียงหนึ่ง dataset, หนึ่ง subject split และสาม seed

เมื่อจำลองการหายไปทั้ง sensor group ผลขึ้นกับว่า sensor ไหนหาย เช่น ที่ 5% ไม่มี gyroscope, SSL-channel ได้ 50.07% เทียบ supervised 37.40%; แต่เมื่อไม่มี accelerometer ในเงื่อนไขเดียวกัน supervised ได้ 44.84% และ SSL-channel ได้ 28.75% ดังนั้นงานนี้ไม่สนับสนุนคำกล่าวว่า SSL แบบใดแบบหนึ่ง robust ต่อ sensor outage ทุกกรณี

## ขั้นตอนที่ทำจริง

1. ตรวจงานเดิมและพบว่า time-channel masking กับ missing-sensor robustness มีผู้ทำก่อนแล้ว จึงตั้งงานเป็นการศึกษาเชิงทดลอง ไม่อ้างว่าเป็นอัลกอริทึมใหม่
2. เลือก UCI HAR และใช้สัญญาณ total acceleration XYZ กับ gyroscope XYZ จำนวน 6 ช่อง หน้าต่างละ 128 เวลา; ไม่ใช้ 561 handcrafted features
3. ใช้ official test subjects และแยก validation subjects 4 คนออกจาก official train; คำนวณ mean/std เฉพาะ train
4. ทำ supervised baseline และ pretraining แบบ masked reconstruction 3 รูปแบบ แล้ว fine-tune ด้วยตัวอย่างติดป้ายชุดเดียวกันข้ามวิธี
5. รัน training-label budgets 1%, 5%, 10%, 100% กับ seed 0, 1, 2; จำนวนตัวอย่างจริง 61, 295, 586, 5,844
6. เลือก checkpoint ด้วย validation Macro-F1 แล้วประเมิน test แยก 3 สภาพสัญญาณ
7. คำนวณผลต่างแบบจับคู่ seed และ bootstrap ระดับ test subject 9 คนเพื่อดูความไวต่อผู้ทดสอบ
8. ตรวจ integrity ของทุกผล โหลดโมเดลกลับมาคำนวณซ้ำ สร้างรายงาน PDF กราฟ CSV ต้นฉบับแก้ไขได้ และแพ็กโค้ดกับ checkpoints

## คำถามที่น่าถูกถามและแนวตอบ

**1. Self-supervised learning ใช้ข้อมูลไม่มีป้ายอย่างไร?**  
เราให้โมเดลเห็นสัญญาณที่ปิดบังบางส่วน แล้วให้ทำนายค่าต้นฉบับเฉพาะตำแหน่งที่ปิดบัง โดยค่าจริงของสัญญาณเป็นเป้าหมายฝึกเอง ไม่ใช้ป้ายกิจกรรมในขั้น pretraining จากนั้นจึงนำ encoder มาฝึกจำแนกกิจกรรมด้วยป้ายจำนวนน้อย

**2. ถ้าชุดข้อมูลมีป้ายอยู่แล้ว จะเรียกว่า unlabeled ได้อย่างไร?**  
ใน pretraining เราไม่ส่งป้ายกิจกรรมเข้าฟังก์ชันเป้าหมาย จึงจำลองการมีสัญญาณที่ไม่ได้ติดป้าย แต่ชุดข้อมูลต้นทางมีป้ายจริงเพื่อสุ่ม training budgets และใช้ประเมิน สิ่งนี้เป็น simulation ของ label scarcity ไม่ใช่การเก็บข้อมูลไร้ป้ายภาคสนาม

**3. ทำไมแยกข้อมูลตามคน?**  
หน้าต่างสัญญาณของคนเดียวกันอาจคล้ายกัน หากกระจายหน้าต่างจากคนเดียวกันข้าม train/test ผลอาจสูงเกินจริง เราจึงกันบุคคลไม่ให้ซ้ำข้ามชุด แล้วคำนวณ normalization จาก train เท่านั้น

**4. ทำไมใช้ Macro-F1 แทน accuracy?**  
Macro-F1 ให้ทุกคลาสน้ำหนักเท่ากัน จึงช่วยเห็นกรณีโมเดลพลาดบางกิจกรรมมาก แม้ accuracy รวมยังสูง รายงานมี accuracy และผลรายคลาสประกอบ แต่ตัวชี้วัดหลักที่กำหนดก่อนดูผลคือ Macro-F1

**5. ผลหลักคืออะไร?**  
ใน clean test SSL-time ดีขึ้น +3.48, +2.01, +1.33 และ +0.35 จุดเปอร์เซ็นต์ที่ training-label budgets 1%, 5%, 10%, 100% ตามลำดับ; ความได้เปรียบลดลงเมื่อมีป้ายมากขึ้น การรวม time+channel ไม่ใช่ตัวเลือกที่ดีที่สุดในชุดนี้

**6. ผลต่าง +3.48 จุดพิสูจน์ว่า SSL ดีกว่าแน่นอนหรือไม่?**  
ยังไม่ใช่ข้อสรุปทั่วไป ตัวเลขเป็นค่าเฉลี่ยสาม seed บนหนึ่ง subject split การวิเคราะห์ bootstrap ระดับผู้ใช้สำหรับกรณี 1% ให้ช่วง 95% เชิงสำรวจประมาณ +0.77 ถึง +5.99 จุด แต่มี test subjects เพียง 9 คน และไม่ได้แก้หลายการเปรียบเทียบ จึงต้องทดลอง dataset และ split อื่นก่อนกล่าวกว้างขึ้น

**7. ทำไม combined masking ไม่ดีที่สุด?**  
ใน protocol นี้ combined mask ปิดข้อมูลประมาณ 37.5% เทียบ temporal 25% และ channel 16.67%; ความยากของงาน reconstruction จึงต่างกัน ผลทดลองบอกเพียงว่าการตั้งค่านี้ไม่ได้ช่วยเสมอ ยังบอกสาเหตุไม่ได้โดยตรง ต้องทดลองให้สัดส่วนที่ปิดเท่ากันก่อนแยกผลของรูปแบบ mask

**8. ถ้า accelerometer หาย ทำไมบางวิธีแย่กว่า supervised มาก?**  
นี่คือข้อค้นพบของ stress test แบบปิด 3 แกนพร้อมกัน โมเดลอาจพึ่งข้อมูล accelerometer ต่างกัน แต่การทดลองนี้ไม่ได้วัด causal feature importance จึงไม่ควรฟันธงสาเหตุ อีกทั้งตอน pretraining ปิดเพียงหนึ่งในหกช่อง ไม่เหมือนการปิดทั้งกลุ่ม accelerometer ตอนประเมิน

**9. 1% หมายถึงใช้ป้ายทั้งหมดเพียง 1% ใช่ไหม?**  
ไม่ใช่ หมายถึงป้ายใน training เท่านั้น ในการเลือก checkpoint เราใช้ validation labels เต็ม 1,508 หน้าต่าง จึงไม่ควรอ้างต้นทุนติดป้ายรวมเท่ากับ 1%

**10. ความใหม่ของงานคืออะไร?**  
ตอนนี้เป็น empirical study ที่ให้ผลเปรียบเทียบแบบควบคุมและตรวจซ้ำได้ ภายใต้ label budgets และการจำลอง sensor outage ความใหม่เชิงอัลกอริทึมยังไม่ยืนยัน เพราะ time-channel masking และ masked sensor modeling มีงานก่อนหน้าแล้ว หากต้องการส่งงานประชุมที่ต้องมี method contribution ต้องร่วมกับอาจารย์กำหนดคำถามที่ยังไม่มีคำตอบและทดลองเทียบงานล่าสุดอย่างตรง protocol

**11. ทำไมไม่มี TS-TCC, TS2Vec หรือ RobustHAR ในตารางคะแนน?**  
เราอ้างเป็น related work แต่ยังไม่ได้ reproduce baseline เหล่านั้น คะแนนในบทความต้นฉบับใช้ข้อมูล/การแบ่งชุด/ทรัพยากรต่างกัน จึงไม่ควรนำมาเทียบตัวเลขตรง ๆ งานขั้นต่อไปคือรัน implementation อย่างถูกต้องใน protocol เดียวกัน

**12. จะรันซ้ำและตรวจเลขได้อย่างไร?**  
ใช้ `docs/REPRODUCE.md` ติดตั้ง environment, ตรวจ SHA-256 ของชุดข้อมูล, รัน `run_matrix.py`, ตรวจ `scripts.audit_runs` แล้วสร้างตารางด้วย `scripts.build_report` ทุก run มี config, seed, subject IDs, labeled indices, checkpoints, confusion matrices และ learning curves

**13. ทำไมไม่ได้ตั้ง hyperparameters เพื่อให้แม่นที่สุด?**  
งานนี้ควบคุม architecture และ optimization เพื่อเปรียบเทียบผลของ pretraining ให้แยกได้ การจูนแบบเลือกค่าที่ดีจาก test จะทำให้ผลเอนเอียง หากต้องการเพิ่มคะแนนต้องออกแบบ search budget เท่ากันโดยใช้ validation เท่านั้น และรายงานค่าใช้จ่ายการค้นหาด้วย

**14. อนุญาตให้ใช้ AI ช่วยทำงานหรือไม่?**  
โค้ด การวิเคราะห์ และร่างบทความได้รับความช่วยเหลือจาก AI ผู้วิจัยต้องตรวจและรับผิดชอบผลทั้งหมด และทำตามนโยบายการเปิดเผยการใช้ AI ของมหาวิทยาลัยกับสถานที่ส่งบทความ อย่าอ้างว่าเป็นงานที่ทำด้วยตนเองทั้งหมดหากไม่ตรงข้อเท็จจริง

## ปัญหาที่เจอจริงระหว่างทำและวิธีจัดการ

| ปัญหา | วิธีจัดการ | สิ่งที่ยังต้องระวัง |
|---|---|---|
| เครื่องเริ่มต้นไม่มี PyTorch และไม่เห็น GPU ที่ใช้งานได้ | ติดตั้ง dependencies ใน virtual environment และรัน CPU | การรันบน hardware/เวอร์ชันอื่นอาจให้เลขต่างเล็กน้อย |
| การดาวน์โหลดจาก UCI origin ช้ามาก | ใช้ teaching mirror ของ UCI HAR; บันทึก URL และ SHA-256 ตรวจโครงสร้าง/จำนวนตัวอย่าง/รหัสผู้ใช้ | ไม่ได้เทียบ byte-for-byte กับ origin ที่ดาวน์โหลดเสร็จครบ |
| เทคนิค time-channel masking มีงานเดิม | เปลี่ยนคำอธิบายเป็นการศึกษาเปรียบเทียบ | ต้องหา contribution เพิ่มก่อนอ้าง novelty |
| การรันหลาย seed พร้อมกันทำให้ตัวควบคุมชุดแรกพบโฟลเดอร์ที่อีก process กำลังเขียนและหยุด | ให้ process ที่ถือชุด seed นั้นรันต่อจนเสร็จ แล้วตรวจว่าได้ครบ 48 run และไม่มีโฟลเดอร์ค้าง | แก้ runner ให้ตรวจ protocol ของ run เดิมก่อนข้าม; อย่ารันหลาย controller กับ output root เดียวกันอีก |
| ป้ายกำกับชุด validation ยังมีจำนวนมากเมื่อจำลอง training budget ต่ำ | ระบุงบป้ายเฉพาะ training อย่างตรงไปตรงมา | ถ้าศึกษาต้นทุน annotation รวม ต้องออกแบบ validation budget ใหม่ |
| มี dataset เดียวและ test subjects 9 คน | รายงานผลตามขอบเขตจริงและทำ bootstrap ระดับผู้ใช้เป็นการวิเคราะห์เสริม | ต้องมีชุดข้อมูล/subject split อิสระก่อนสรุปเชิงทั่วไป |

## สิ่งที่ควรตอบเมื่อถูกถามว่า “พร้อมส่งแล้วหรือยัง”

ตอบว่า “ชุดทดลองตาม protocol และรายงานให้อาจารย์ตรวจเสร็จแล้ว ตัวเลขตรวจย้อนกลับได้ แต่ยังต้องใส่ชื่อผู้เขียน เลือกรูปแบบตามเป้าหมาย และเพิ่ม baseline/dataset หากต้องการส่งเป็นบทความที่อ้าง contribution ใหม่” คำตอบนี้ตรงกับหลักฐานที่มีที่สุด
